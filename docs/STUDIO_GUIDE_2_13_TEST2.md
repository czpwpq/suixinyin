# 2.13-test2 使用与真机验收

本版继续使用便捷版包名和原签名，可覆盖便捷版旧版；上游原版是另一个应用，Shizuku 授权互不通用。先确认安装的是“墨水屏便捷版 2.13-test2”（versionCode 19），并按实物选择 A0 / A1。[test1 指南](STUDIO_GUIDE_2_13_TEST1.md)和 [2.12 指南](STUDIO_GUIDE_2_12.md)保留为历史记录。

## 升级后先检查身份，不用贴手机壳

test1 用户日志中的 `SecurityException: Wrong caller` 发生在 NFC 通信之前。报告已经显示当前进程与安装 UID 一致、Shizuku 权限已允许并收到 Binder；test2 用只读后端握手进一步确认服务身份，根因仍待真机反馈。

1. 直接覆盖安装 test2，保留数据与现有授权。本版需要 Shizuku 13 或更新版本；先不用贴手机壳，打开 App 后点击“连接 / 授权 Shizuku”。
2. 等待只读 INFO 身份检查完成：它核对应用包名 / 当前安装 UID、协议、编译后端版本 20、后端 UID 和 APK 路径。只有检查通过才显示已连接；此步骤不寻卡、不发送图片，也不启动刷新。
3. 若提示身份不一致、后端版本不符或仍出现 `Wrong caller`，先复制“Shizuku 连接诊断”及本轮日志。记录本版版本和错误提示，反馈后继续排查；不要反复确认刷写来尝试恢复。
4. 身份检查通过后再贴手机壳，先执行“只读检查屏幕”，通过后手动发送一张简单图片。再验收同页照片、日历和自动任务。

本版按当前 UID 隔离服务，后端从 Context 解析应用身份，继续保留操作调用方 UID 校验。身份错误停止连接，不自动重放之前的写入请求。服务停止 / 重启的通用恢复步骤见下节；它不是对本次根因已经确定的结论。

## Shizuku：连接、授权与列表消失

1. 打开独立 Shizuku，确认首页服务状态；已配对不等于已启动服务。手机重启后通常需重新启动服务。
2. 返回便捷版，点击“连接 / 授权 Shizuku”，在系统弹窗允许。本版会自动连接已有授权的服务，等待授权或后端连接超时后可重新尝试。
3. 如果便捷版在 Shizuku 授权列表出现后又消失，先保留现有安装，去 Shizuku 内停止服务，再重新启动服务；仅划掉管理器后台不等于重启服务。无线调试已配对时通常不必重新配对。
4. 返回便捷版，再从本应用发起授权并允许。若仍无反应，打开“Shizuku 连接诊断与恢复”，选择“重查并请求授权”或“查看 / 复制诊断”。
5. 报告显示应用版本 / 包名、Provider 和权限声明、Shizuku 管理器版本、是否收到 Binder 及授权状态；不读取照片、日志或 Shizuku 私有配置，也不修改系统设置。不需要先卸载、清数据或更改其他 App 的分身设置。

Shizuku 13.6 的列表显示和服务授权配置路径可能有关，这是基于上游实现的排查方向，尚未在你的手机确认。未收到 Binder 也不能直接证明服务没有运行，需结合 Shizuku 首页判断。若问题持续，反馈诊断报告、Shizuku 首页状态及有没有出现过授权弹窗。

## 拍立得 / 自由构图：同一页完成

1. 在“图像与发送”顶部打开“拍立得 / 自由构图”，点“重新选图”；取消相册选择应回到当前创作页。
2. 下方构图区域单指移动、双指缩放，滑杆自由旋转，也可 90° 旋转或重置。选择拍立得相框、白边 / 留白底色、原图 / 黑白 / 暖色风格、题字及文字颜色。
3. 在同页选择实物 A0 / A1、四色映射、抖动算法与强度。顶部会更新**最终四色预览**；下方构图区域用于摆放原图，两者的颜色显示用途不同。
4. 等“正在生成最终四色预览”结束后，核对顶部画面，再点底部“发送到墨水屏”并确认。该次发送使用确认的同一份最终帧，不要求返回主页面重新处理。
5. 生成新预览时暂不可发送；刷写期间编辑锁定。需要中断时点“停止发送”，等待当前通信结束。全程保持解锁、应用前台及 NFC 贴合；完成提示后目视确认画面。

精确四色预览只保证发送像素一致，不代表手机屏幕发光颜色与墨水屏反射颜色相同。抖动不会使固定尺寸全帧天然变少，也不能据此证明供能不足已修复。

## 日历：四套模板和天气

“日历卡片”选择版式：

- 竖屏 · 清爽月历：月历为主，底部天气信息。
- 竖屏 · 大字日期：突出标记日与星期。
- 横屏 · 月历天气：月历和天气并排。
- 横屏 · 本周与月历：大日期、天气及高亮所在周。

四套均使用公历、周一开始及完整六行布局，增加黄色标题 / 信息区，可调强调色和底色。选择月份 / 标记日期后，日历、星期及本周范围随之变化。横版预览按横向显示；发到物理屏幕的帧仍是 552×768，实际观看需把手机壳横放，不必额外旋转发送图。

城市、天气与温度可以直接手动填写。也可输入城市名或拼音，点击“搜索城市并获取天气”，从候选城市中选择地点。只有主动获取时才联网；不申请 GPS / 定位权限，不需要 API Key。城市搜索把输入的城市名发送至 Open-Meteo，天气请求仅使用所选地点坐标；不会发送照片、便签、设备 UID 或 NFC 日志。

成功后显示 Open-Meteo 来源与服务返回的时间 / 时区。该时间表示天气数据时刻，不是重新打开页面或生成预览的时刻。保存的旧天气不会因为生成新日历而自动变成“最新”；需要更新时再次主动获取。直接编辑城市、天气或温度会切回手动内容，不再把修改后的文字当作 API 原始结果。网络失败保留现有内容，可手动编辑后继续使用。

天气是模型数据，不能当作手机实测。横竖模板对长城市名、标题、温度和记录文字会缩小或省略，请在发送前检查预览。当前不包含农历 / 节假日数据库，也不做后台天气自动更新。

## 便签、时钟与四色处理

便签支持中文手动换行、字号、粗体、四色文字 / 底色 / 描边；超长内容缩小或省略。避免文字和底色完全相同，并检查最终预览。

时钟支持数字 / 指针，使用手机当前时区，不显示秒。它是刷新时刻的静态画面；移开手机后不会自行走时。显式开启时钟定时刷写后，每轮完成再开始下一段等待，不保证准点报时。

照片同页提供色彩映射、抖动算法和强度，默认是感知色彩 + 蛇形 Floyd–Steinberg + 75%。还可选择原版 RGB、实验暖调、Atkinson、Bayer 4×4 或 Sierra Lite。之前出现过供能 / 刷写失败时，初次先关闭抖动、用简单图片试刷，再逐项对比；这不保证修复供能问题，也不代表完成了实屏色彩校准。文字卡片默认关闭照片增强及抖动，保护清晰色块；实体色彩仍需同图对照。

## 多图轮播与中止

选择最多 30 张图片后，图片复制到应用私有存储；新列表替换旧列表。选择 1 分钟至 24 小时间隔并明确确认开始，首轮立即运行，每轮完整结束后再等待。时钟自动模式按当前手机时间重新生成画面。

手机必须保持解锁、App 前台和 NFC 贴合。停止、离开、锁屏、失去授权、目标改变、读取失败、刷新失败或结果未确认都会结束任务，不会自动续写、并发补刷或重发刷新指令。首轮后只接受同一 UID。列表可保留，但运行状态不跨 App 重启恢复。

## 建议真机验收顺序

- [ ] 同签名覆盖安装成功，版本为 2.13-test2 / versionCode 19；原便签、照片及 A0 / A1 设置正常。
- [ ] 不贴手机壳时连接能完成只读身份握手，显示的后端版本为 20；失败时报告及本轮日志可复制。
- [ ] 身份握手通过后，先执行硬件只读检查，再确认发送简单图；身份错误不会自动重放先前的写入。
- [ ] Shizuku 已运行授权后自动连接；授权拒绝、请求超时、后端绑定超时后能重新请求，不永久卡在等待状态。
- [ ] 只读诊断可查看和复制；停止 / 启动 Shizuku 后可重新授权。列表消失的实际现象、系统与管理器版本均有记录。
- [ ] 相册选择 / 取消、单指移动、双指缩放、旋转、相框与无框模式正常；修改后旧预览不可误发。
- [ ] 同页四色预览、确认与刷写内容一致；发送中不能继续改参数，停止后等待本轮结束。
- [ ] 四套日历均可查看；六行月份、闰日、跨月本周范围、黄色信息区和横版方向正常。
- [ ] 手动天气不要求联网；城市搜索能选候选地点，获取成功显示 Open-Meteo 与实际数据时间。
- [ ] 旧天气不自动更改时间，手动改写后来源转为手动；断网 / 无结果 / 服务失败时保留原画面并可编辑。
- [ ] 便签长中文、红黄文字、描边、静态数字 / 指针时钟正确；开启两图轮播后间隔与停止条件符合说明。
- [ ] 锁屏、离开 App、Shizuku 停止、移开屏幕或换屏后不会无提示继续刷写。

## 开发者原生渲染测试与验证边界

设置 `JAVA_HOME`、`ANDROID_HOME` 和与主 APK 相同的签名环境变量，构建主 APK，再运行 `python tests/android/build_card_tests.py`。安装主 APK 及测试 APK 后运行：

```text
adb shell am instrument -w org.nfcresearch.qpolllab.cardtests/org.nfcresearch.qpolllab.CardRendererInstrumentation
```

必须实际看到测试通过并核对导出的 PNG，才能标记原生绘制通过。当前开发环境没有连接 adb 设备 / 模拟器 / 硬件；Fake Binder 身份测试也属于尚未在 Android 上执行的设备侧测试，编译通过不能当作执行通过。test2 的最终回归、打包、签名与真机状态见 [VALIDATION_2_13_TEST2.md](VALIDATION_2_13_TEST2.md)。用户的 test1 天气数据截图只验证了该版对应界面路径，不证明 test2 连接或 NFC 已通过。

GitHub 仓库、Actions 和正式 Release 仍待用户真机验收后处理。反馈时附版本和复现步骤，公开报告前检查设备标识；私人照片不放入源码包或 GitHub。
