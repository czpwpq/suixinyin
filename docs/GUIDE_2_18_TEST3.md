# 随心印 2.18-test3 · 动漫人物大图版式

覆盖安装后打开“动漫人物生日”即可看到新布局，无需重新获取已有画像。编辑完成回到首页核对，再手动推送；墨水屏上已有的旧图片不会自动更改。

生日卡片使用独立紧凑顶栏，标题与日期并排。图片区由448×280改为496×500，完整容纳竖版人物图；姓名、作品和生日集中排在下方。按典型3:4图片估算，实际画像由210×280增至375×500，面积约为原来的3.2倍。图片保持原比例，不拉伸、不默认裁切人物。

继续隐藏生日底部来源和核对说明，保留人物选择、画像归属检查、缺图占位及失败提示。其他卡片、照片编辑和推送流程沿用2.18-test2。

## 关于局部刷新和TXT

当前App每次发送552×768的完整画面（105984字节），由D3上传后执行板内D4刷新流程，再用DE等待结束。没有接入已经验证的阅读器式快刷、差分刷新或局部波形切换。

“每5–10页做一次全刷”的计数逻辑可以实现，但前提是屏幕与驱动先有可用的快速刷新模式。单纯把画面改成黑白、只在App内重画部分区域或跳过清屏，不能据此认定实体屏已经局刷。

2026-10-25核查到相关上游已有A0/A1实验分段方案，但作者不保证另一段画面保持不变，且保留原厂驱动模式不能与分段共用。改用自定义驱动会覆盖原厂配置，该工具目前无法还原。这说明有研究空间，不能据此断言硬件绝对无法局刷，也不能把实验分段当作已验证的阅读器快刷。

参考：[上游使用限制与原厂驱动说明](https://github.com/solar2ain/ink-nfc-fmsc-by-pn532#使用限制)、[协议与窗口说明](https://github.com/solar2ain/ink-nfc-fmsc-by-pn532/blob/main/docs/protocol.md)。本次没有移植、执行该项目的驱动或分段代码，也未向屏幕发送实验指令。D4的P1/P2位级定义尚未取得可核实的厂商依据，不能将某一固定参数擅自解释成局刷开关。

TXT导入、分页和字号排版可以另行实现；按目前已验证的通道，每翻一页仍需完整传图与刷新，并保持手机NFC贴合供电。实际翻页时间应以完整会话实测为准。这个版本只扩大人物画像，没有新增TXT阅读器或改写屏幕驱动。

原生渲染测试只编译，实屏人物大小、姓名和作品的可读性仍需真机确认。
