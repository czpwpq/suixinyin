## test2：先核对后端身份，再进入刷屏

用户在 test1 的日志出现 `SecurityException: Wrong caller`，错误发生在 NFC 通信之前。现有诊断中 Android 用户为 0，进程 UID 与安装 UID 一致，Shizuku 权限已允许且已收到 Binder；根因仍需新版本的后端握手结果确认。

test2 将编译后端版本提升为 20，按当前应用 UID 隔离服务标记，并通过 Shizuku 13 或更新版本传入的 Android Context 确定后端绑定的应用身份，不固定查询用户 0。操作事务继续严格校验调用 UID；新增只读 INFO 握手，验证应用包名 / 安装 UID、协议与编译版本、后端 UID 和 APK 路径后，才显示已连接。身份不匹配时记录诊断并停止，不自动重放写入。

本版 `versionCode=19`，包名和签名保持一致。先覆盖升级，**暂不贴手机壳，只点击连接，完成身份握手**；不一致时复制连接诊断及本轮日志，确认身份通过后再执行硬件只读检查和手动刷写。步骤见 [当前指南](STUDIO_GUIDE.md)。

## 2.13 新增与改进

- **同页创作与发送**：拍立得 / 自由构图中选择图片、拖动缩放旋转、调整相框 / 题字 / 四色映射 / 抖动，顶部直接显示最终四色预览；点击发送并再次确认后使用该份固定像素快照，不必返回主页面重新处理。生成新预览时暂停发送，刷写期间锁定编辑。
- **日历四套模板**：竖屏清爽月历、竖屏大字日期、横屏月历天气、横屏本周与月历；增加黄色信息区与强调色。横版预览可直接横向阅读，发送帧仍为 552×768，实体手机壳需横放观看。继续支持公历、标记日、长标题和完整六行月份。
- **手动或联网天气**：城市、天气、温度可直接填写；也可主动点击城市搜索，选择地点后获取 Open-Meteo 天气。联网结果标注数据来源与服务返回的时间 / 时区，手动改写后切回手动天气。不会后台自动刷新天气，旧数据保留原时间。
- **Shizuku 连接诊断**：增加只读报告和恢复入口，显示应用声明、管理器版本、Binder 与授权状态。授权请求或后端绑定超时后可重新尝试；不会在后台偷偷重发刷屏指令。

Shizuku 13.6 中“应用出现后又从授权列表消失”可能涉及上游管理器授权列表和服务授权配置的路径；这是排查方向，尚未在你的手机上确认根因。本版提供保留已安装应用的恢复步骤：在 Shizuku 内停止服务并重新启动，返回本应用再次请求授权。仅划掉管理器后台不等于重启服务；不需要先卸载应用或清除数据。

## 网络与图片

2.13 增加 `INTERNET` 权限，仅在主动查询天气时使用：城市搜索向 Open-Meteo 地理编码服务发送你输入的城市名，获取天气向其天气服务发送所选地点的经纬度。无需 GPS、定位权限或 API Key。照片裁剪、四色转换、模板与 NFC 传图仍在本地完成，不向天气服务上传照片或便签内容。网络失败保留原内容，可继续手动填写；本地模式不依赖联网。

天气是 Open-Meteo 在返回时间对应的模型数据，不能把该时间写成手机实时测量或本次预览生成时间。来源与接口说明：[天气 API](https://open-meteo.com/en/docs)、[城市搜索 API](https://open-meteo.com/en/docs/geocoding-api)。

# 墨水屏便捷版 · 2.12-test1（历史记录）

在本项目既有 Android NFC 后端上增加本地创作功能；延续原版 A0/A1 屏幕协议及权限要求。2.11 功能及上游文档保留在下方。

## 新功能

- **拍立得**：单指拖动、双指缩放、任意角度及90°旋转；可选相框留白、底部文字、黑白/暖色风格。主页面显示最终四色像素。
- **便签**：中文换行、字号、粗体、四色字体/底色/描边；超长文字自动缩小，仍超出时省略。
- **公历日历**：选择月份、标记日期、自定义标题、强调色和底色；正确处理闰年与六行月份。不含农历或节假日数据库。
- **时钟**：数字/指针、手机当前时区、日期与星期；可手动写入，也可显式开启前台定时刷新。
- **四色处理**：原版 RGB、感知色彩、实验暖调；蛇形 Floyd–Steinberg、Atkinson、Bayer 4×4、Sierra Lite 四种抖动及0–100强度，支持关闭。
- **多图轮播**：最多30张，复制到应用私有存储；间隔1分钟至24小时，每轮完整结束后计时，无并发、无错过补刷。

## 定时模式的实际边界

手机需保持解锁、应用前台、与屏幕贴合，每轮由手机 NFC 重新供能写入。时钟图像是生成时刻的静态快照，不是秒级时钟，也不会在移开手机后自行走时。

停止、离开应用、锁屏、失去连接、通信失败、活动会话标签离场或刷新未确认均停止当前定时任务，不会恢复后自动续写。首轮确认目标后，后续轮播只接受同一 UID。刷新指令不自动重试。

基于 [ZhaoGY-N/huawei-nfc-eink-android-app](https://github.com/ZhaoGY-N/huawei-nfc-eink-android-app) 的实验性修改版。原作者及协议研究者的版权、许可证和通知均保留。上游版本说明见文末。

## 本版改动

- 已启动、已授权的 Shizuku 在进入 App 时自动连接；从 Shizuku 返回后自动尝试连接。
- 顶部显示服务未启动、待授权、连接中、已连接、超时等状态，并提供启动入口。不会自动执行刷屏；发送仍需确认。
- 默认进入图像页，记住 Root/Shizuku 选择；已 Root 用户仍可选择原有 Root 后端。
- 在手机本地调整亮度、对比度、饱和度、暗部提亮；提供原版兼容、照片增强、浅色插画、纯四色素材预设。
- 实验性“亮度优先四色”支持原版对照，近中性灰只在黑白之间选择；保留二值化、色块简化和抖动。预览与发送来自同一份量化像素。
- 原版兼容为中性参数 + 原版量化；选择预设会关闭抖动、二值化和色块简化，之后可自行调整。参数保存在本地，不代表已校准实体面板。
- 独立包名 `org.nfcresearch.qpolllab.easy`，可与原版共存，显示为“墨水屏便捷版”。首次须单独在 Shizuku 授权，并选择实物屏幕类型。

## 上游 README（保留供参考）

# Huawei NFC E-Ink Android App

Android 墨水屏刷新工具，当前测试版本 **v2.10-test1**。通过 Shizuku 或 Root 调用兼容系统的 NXP Q-Poll，再通过 Android ISO-DEP 向 **552×768 四色华为 A0 / A1 墨水屏**传图刷新，使用板内已存驱动。

## 功能

- 设备与测试：授权连接、NFC 芯片配置识别、Q-Poll 能力测试、普通 NFC-A 对照。
- 图像与发送：选图、四色预览、旋转、裁切、黑白二值化、阈值、色块简化和抖动；支持全屏缩放与 1:1 像素查看。
- 预览和发送按钮位于页面上方，图片编辑选项位于下方；预览高度根据可用空间调整。
- 高级参数：上电等待时间、忙状态查询间隔；参数保存在本地。
- 保留屏幕规格和原厂扫描配置检查，不限制屏幕 UID；发送前确认，运行中可停止。

## 使用

1. 开启 NFC，保持手机解锁。启动 Shizuku 后，在“设备与测试”页授权连接；也可选择 Root 后端。
2. 点击“检查芯片 / NFC”，按需测试 Q-Poll。型号来自系统固件配置，能力以实际控制器响应和通信结果为准。
3. 在“图像与发送”页手动选择实物屏幕类型 A0 或 A1，再选择图片并调整预览，可先执行“只读检查屏幕”。选择会保存，更换屏幕时需重新核对；D1 无法自动判断 A0 / A1。
4. 点击“发送当前预览到墨水屏”，核对图片和参数后确认。持续贴合并保持应用在前台，直到操作结束。

仅适用于兼容 Q-Poll 的手机系统及相同原厂配置的目标屏；不能仅凭接口存在或型号名称判定兼容。刷新结果取决于实际供能与屏幕状态。中断可能留下不完整画面，程序不会自动重发刷新指令。

## 构建与验证

需要 Python 3、JDK 17、Android SDK platform android-34 和 build-tools 34.0.0。设置 `JAVA_HOME`、`ANDROID_HOME` 指向本机安装目录，然后在仓库根目录运行：

```sh
python3 tests/run_java.py
python3 build.py
```

脚本使用 Android SDK 的命令行工具构建，无 Gradle、无构建期下载。Shizuku API / provider / aidl / shared 13.1.5 依赖已固定在 `libs/`。构建脚本当前使用 Unix 工具路径；Windows 可在 WSL 中运行。

如安装了 `lzokay==2.1.0`，可独立检查解压与扫描打包：

```sh
python3 tests/check_fixtures.py build/<protocol-tests-directory>
```

APK 和 SHA-256 输出在 `dist/`。首次构建会在 `build/` 生成本地调试签名密钥；密钥、构建缓存和 APK 不纳入 Git。自行构建时需要保留自己的密钥，以支持后续覆盖安装。

```sh
adb install -r dist/QPollLab-2.10-test1.apk
```

## v2.9.1 配置诊断

配置校验失败时，日志逐项显示不匹配字段、期望值和实际十六进制值；缺失或长度异常也显示对应字段。D1 只检查首字节时明确标注。仍执行原有兼容性检查，校验失败后不会认证、传图或刷新，不改写 DB/DA。UID 不参与兼容性校验。

## v2.9.2-test1 连接测试版（Issue #1）

针对寻到标签后 ISO-DEP 连接失败，增加最多三次连接尝试：仅 `IsoDep.connect()` 抛出 IOException、尚未发送任何 APDU 时重新启动 ReaderMode，获取同一 UID 的新 Tag；重新寻卡超时、取消或遇到不同 UID 即停止。协议通信开始后不自动重试，保留原有屏幕规格校验。

日志增加 CONNECT_ATTEMPT、ISO_DEP、CONNECTED / CONNECT_FAILED、APDU_BEGIN / APDU_FAILED 和异常堆栈；不记录 PIN 或图像内容。升级后重新连接 Shizuku，先执行“只读检查屏幕”，反馈从本轮开始到结束的完整日志及手机、系统、屏幕型号。此版本是连接恢复尝试与诊断增强，尚未在 Issue 中的目标屏实测，不代表已支持该型号。

## v2.10-test1 手动选择 A0 / A1

- “图像与发送”页新增屏幕类型选项，首次使用必须明确选择；不根据 D1、UID 或旧版设置猜测型号。切换后重新生成发送快照，运行中不能更改；发送确认和日志显示所选类型。
- A1 保留原有线性控制器行布局，A0 使用参考仓库的奇偶行交错布局。预览按所选布局反解，显示逻辑画面，而非交错后的传输排列。
- 继续使用板内已存驱动，不发送 DB / DA。不负责将 A1 驱动板重配为 A0 或反向改装；实物与板内驱动必须对应。
- 接受已知的 `00120030FFFFFF` / `01120030FFFFFF` 扫描配置，并按读出的方向调整传输数据；其他规格校验仍然保留。写入前复核发现方向变化即停止，不传图。
- 预览快照 SHA-256 与实际发送 SHA-256 分别记录；扫描方向转换发生在 D1 校验之后。只读检查仍可在未选择型号时执行，但不能据此识别 A0 / A1。
- 全帧映射与参考打包函数逐字节比对通过，回归覆盖两种型号、两种扫描方向、实际 D3 数据、预览还原及未知选择拒绝；APK 构建和签名验证通过。尚未完成两种实物屏的刷新验证；此改动不解决 D1 返回 `6401` 的问题。
